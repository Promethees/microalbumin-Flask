Everything the banner needs — markup, styles, behaviour — lives in this one file, for two reasons: * Taking the banner down is deleting this file and its two {% include %} lines. Nothing is left behind in landing.css or style.css. * Both pages load *minified* stylesheets from static/dist when PRODUCTION_MODE is on, so a rule added to landing.css or style.css would not reach production until the next `npm run build`. Inline styles ship with the template. The two pages have unrelated design systems (landing = petrol/spectral, web app = indigo/glass) and different dark-mode hooks (`html.dark` vs `body.dark`), so the banner carries its own dark palette and matches on both selectors rather than borrowing either page's tokens. ───────────────────────────────────────────────────────────────────────── #}
